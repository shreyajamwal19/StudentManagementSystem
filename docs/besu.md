# Hyperledger Besu QBFT network

## Why Besu and QBFT
- **Besu** is an enterprise Ethereum client with permissioned-network features, supporting Solidity and standard JSON-RPC/Web3 tooling, so the contract and web3 client code work unchanged on a private chain.
- **QBFT** (Quorum Byzantine Fault Tolerant) is a validator-based consensus protocol with **immediate finality**: once a block is committed it cannot be reorganized. That suits audit records. It tolerates `f` faulty validators out of `3f+1`; we use 4 validators (f = 1).
- **Validators** are the nodes allowed to propose and vote on blocks. Each round one validator proposes a block (round-robin); the others verify it and exchange prepare/commit votes; with at least 2f+1 commits the block is sealed.
- **Transaction confirmation:** a signed transaction goes to a node's mempool, is gossiped, included by the next proposer, and is final when that block is committed (about one block period, 2 s here).

## Configuration (`besu-network/qbftConfigFile.json`)
chainId 20260, QBFT `blockperiodseconds` 2, `requesttimeoutseconds` 4, `epochlength` 30000, London+Shanghai from genesis, `zeroBaseFee` and `--min-gas-price=0` (private network, gas is free), 4 generated validators.
RPC is bound to 127.0.0.1 with only ETH, NET, QBFT, WEB3 APIs. Validator private keys are generated by `setup.sh` into `networkFiles/` and `nodes/` (gitignored, never committed).

## Run (local, native)
Requires Java 25 and the Besu tarball (tested: Besu 26.10.2, tarball SHA-256 `8cc633e19cb23cd38b5d6ad988b725c8533389a773aea65782fd16d37946825b`).
```bash
export BESU_BIN=/path/to/besu-26.10.2/bin/besu
cd besu-network && ./setup.sh && ./start.sh      # 4 validators: p2p 30303-30306, RPC 8545-8548
pip install web3 && python3 verify_network.py [--fault-test]
./stop.sh        # ./reset.sh deletes chain data and keys (destructive)
```
web3.py needs `ExtraDataToPOAMiddleware` for QBFT because block `extraData` is longer than 32 bytes.

## Verified results (actual run, `experiments/results/besu_network_verification.json`)
- Client `besu/v26.10.2`, chainId 20260, 4 validators, every node sees 3 peers.
- Block time exactly 2 s; all 4 validators proposed blocks within the last 12 blocks.
- A real signed transaction (ephemeral throw-away key) was included in a block, receipt status 1, and the same receipt was returned by a different validator.
- Fault tolerance: one validator down, blocks continue; two down, the chain halts (fewer than 2f+1 validators); after restart it resumes.

## Limitations
- This run was on a 1-CPU, 4 GB sandbox; timings are not representative of benchmark hardware. Final numbers come from your machine.
- Node permissioning (allow-listed enodes) and accounts for Faculty/Moderator/Admin signers are added in later milestones.
- Docker Compose version of this network is not included yet (not tested).
